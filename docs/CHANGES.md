# Changes in CoD2rev-Plus

Everything this fork adds to [voron00/CoD2rev_Server](https://github.com/voron00/CoD2rev_Server), in detail: the functions, variables and fixes behind each milestone that the [README](../README.md#changes-in-this-fork) summarizes. The script functions marked as coming from [zk_libcod](https://github.com/ibuddieat/zk_libcod) keep its names and arguments, so scripts written for it run here.

## Building and running

- **Windows build with MinGW** (32-bit), including cross-compiling from Linux.
- **Game version selectable at build time:** the server can be built as 1.0 or as 1.3.
- **Hardened builds:** the stack protector, `_FORTIFY_SOURCE` checks and, on Linux, read-only relocations are on, so many buffer overflows stop the server instead of being exploitable. `-fno-strict-aliasing` and `-fwrapv` keep the reversed code, which casts between types and relies on signed overflow wrapping, correct at higher optimization levels.
- **Simpler builds:** `make` builds the 32-bit Linux binary directly, `make windows` cross-compiles for Windows, and GitHub Actions builds every variant on each push.
- **Example `server.cfg`:** `scripts/server.cfg.example` lists every variable the server registers; `scripts/gen_server_cfg.py` regenerates it from the source.
- **Launchers:** `scripts/windows/iniciar_cod2rev.bat` and `scripts/linux/iniciar_cod2rev.sh`, with a LAN mode and an internet mode.

## Security and stability

- **Rcon lockout after failed attempts:** after several wrong passwords, the IP address is ignored by rcon for a while. A correct password resets the counter, every wrong guess counts (also those dropped by the global rate limit, which a guesser with many addresses could otherwise hide behind), and `127.x.x.x` addresses and those in `sv_rconWhitelist` are never locked, so spoofed guesses cannot lock out the admin.
- **Bounded strings in libcod script functions:** the libcod `printf` and `sprintf`, the asynchronous SQLite and exec calls and the player rename no longer write past their buffers when a script passes long strings. `findConfigStringIndex` and `findConfigStringIndexOriginal` check that the whole range they search exists instead of only its ends, and `toUpper` no longer returns unterminated text for strings of 1024 characters or more (they are cut to 1023). On Windows, manymaps and `file_link` create and remove links with the system calls instead of `del` and `mklink` commands built from unquoted paths, which broke on spaces and could run other commands.
- **libcod SQLite, exec, JSON and MySQL fixes:** an array or struct passed to an async SQLite or exec call is kept until its callback runs, and an async entity query whose entity is deleted meanwhile skips its callback instead of running it on another entity. An exec callback that calls `exec_async_checkdone()` no longer runs itself again until the server crashes. A failed async SQLite query is printed to the console instead of raising a script error that repeated on every `async_sqlite_checkdone` and held back all later results. Async queries no longer reserve 4 MB each or stall `sqlite_open`/`sqlite_close` while the worker runs, queries longer than 1024 characters are no longer cut, and `sqlite_query` returns NULL columns as `""` so later columns keep their index. `json_stringify` and `json_save` turn an array with gaps in its indexes into a JSON object instead of dropping the indexes, and `json_save` refuses names ending in a dot or a space or containing `:`, which on Windows could still write a `.cfg`. `mysql_real_connect` and `mysql_async_initializer` no longer crash the server when the connection fails, and `binarybuffer_write` raises an error for a value of the wrong type.
- **Network input hardening:** a connected player could crash the server or overwrite its memory with an oversized compressed message, a fragmented message, a name containing `%` (written to the log by the stock gametypes), `callvote clientkick` with a negative number or voice packets. These paths are now bounds-checked, and the file handles of interrupted HTTP downloads are closed.
- **libcod proxy address and downloads:** the real address that a local proxy passes in the `ip` userinfo key is only trusted from `127.0.0.1`, must be an IPv4 address and is cleared on every connect. A `donedl` from a player already in the game no longer makes the server resend the whole gamestate.
- **Downloads and passwords:** the check meant to stop clients from downloading the stock `iw_*.iwd` files never matched, so any client could fetch them (hundreds of MB each); they and the server-only `_svr_` iwds are now refused, also before an HTTP redirect. Downloads no longer get stuck when the map changes during one, a client message too large to decompress drops the client instead of being cut short, and rcon, `g_password` and `sv_privatePassword` are compared in constant time.
- **Bans, game log and other fixes found in zk_libcod:** `addip` and `g_banIPs` kept a list of banned addresses that nothing checked; it is now enforced on connect, also for players behind a local proxy. The last address in `g_banIPs` is no longer skipped, and a long `addip` no longer overflows the stack. Line breaks in chat messages and player names could write fake lines into `games_mp.log` and split `getstatus` replies; they are now removed. A wrong rcon password no longer holds up the right one, a `userinfo` no longer swallows the next chat message, and holding the grenade button without grenades no longer hides the player's shots and footsteps from the others. The effect entities of grenade explosions are now freed instead of piling up until the map ends, a script that deletes a turret in use no longer ends the map, and a long map name passed to a script function no longer stops the server.
- **Map names, format strings and script values:** `map` from the console or rcon with a name of 64 characters or more, and `callvote map` or `typemap` with exactly 64, overflowed the map name buffer; they are now refused. Errors that put a script, entity or file name into their format string (an unknown weapon in `getWeaponModel`, an animtree, a `trigger_radius`, an impure iwd) printed garbage or crashed when the name contained `%`, and errors while parsing script data files printed the wrong file and line and could crash. The script runtime error dialog and the `Couldn't load file` error now include the message and the file name, and the compiler checks the format strings of the print and error functions (`-Wformat`). `setcvar` and `makeCvarServerInfo` now store the value with double quotes turned into single quotes, as their cleaning step intended. The bad rcon message and the netchan statistics keep working after the millisecond counter wraps, and master and authorize ports above 32767 are no longer printed negative.
- **Crash reports:** when the server crashes, it writes the signal or exception, the faulting address and the call addresses to the console and to `crash.log` in `fs_homepath`. `addr2line -f -e <binary> <address>` turns them into source locations. On Linux the process then dies with the same signal as before, so core dumps still work. Every worker thread (SQLite, MySQL, exec, sounds, JSON, HTTP and WebSocket) gets its own alternate signal stack, so a stack overflow there is reported too instead of killing the server silently, and a failed thread creation prints its real error. An async SQLite query whose worker thread can't be started now raises a script error instead of waiting forever.

## Compatibility and server behaviour

- **Master servers:**
  - `sv_master2` is preset to `master.cod2x.me`, the CoD2x community master.
  - The `host:port` format in `sv_master1`–`sv_master5` now works.
  - A DNS failure is retried instead of clearing the master.
  - On Linux, `+set sv_master2 ""` on the command line now clears the master. The empty argument used to vanish, so `set` changed nothing and the server kept sending heartbeats to it.
- **Overflow fix for Game Pass clients:** sending the system info to a client using protocol 119 could overflow a buffer and crash the server.
- **Large messages from 1.3 clients:** fragmented messages sent by 1.3 clients were misread and dropped; they are now read in the 1.3 format.
- **`dedicated` is honoured:** `+set dedicated 1` was ignored and every server announced itself to the master servers. Now `1` keeps the server off the public list and `2`, the default, announces it.
- **Game files on Windows drives:** the Linux build could not see the game files on file systems with large inode numbers, such as Windows drives under WSL. It is now built with 64-bit file offsets.
- **Steady game clock on Linux:** the server measured time with the wall clock, so every clock correction (NTP, virtual machine time sync) froze the game for a moment. It now uses the monotonic clock.
- **Bots after a map change:** after a map change, bots stayed connected but out of the game, holding their slots, so the bots mod kept adding more until the server was full. They now come back into the game as soon as the new map loads.
- **Fewer stalls and a cleaner startup:** the master server name is resolved once instead of on every authorization timeout, and the server no longer warns about every `+set` on the command line.

## Administration

- **Passwords kept out of the log:** `rcon_password` and `sv_privatePassword` are shown as `********` in the console log.
- **Logging and admin settings:** the console log can be renamed (`logfileName`), keep the logs of previous runs (`logfileRotate`) and start each line with the date and time (`logTimestamps`). Accepted rcon commands can be left out of the log (`sv_logRcon`), the CD key authorization server can be changed (`sv_authorizeServer`, `sv_authorizePort`), the server can impose a rate and snapshot rate on every client (`g_forceRate`, `g_forceSnaps`), and the messages announcing a kick or a timeout can be turned off (`sv_kickMessages`, `sv_timeoutMessages`). The names are the same as in zk_libcod, so its configs keep working.
- **Clean shutdown on Linux:** SIGTERM, SIGINT (Ctrl+C) and SIGHUP make the server quit as the `quit` command does: players get the final message, the masters the flatline heartbeat, and `games_mp.log` and the console log are closed (with `g_logSync 0` the last lines used to be lost). A second signal while it quits exits at once, a signal that `nohup` or the shell ignores stays ignored, and SIGPIPE is ignored. On Windows, logging off or shutting down the system now quits the same way; closing the console window already did.
- **Console log errors:** when the console log can't be opened (a read-only `fs_homepath`, a bad `logfileName`), the server prints the reason once and tries again only when `logfile` or `logfileName` changes. It used to print that the log was opened, retry on every line printed and rotate the older logs away with `logfileRotate` on each retry.
- **Game log rotation:** with `g_logRotateSize`, a `games_mp.log` that has reached that size is renamed to `games_mp.log.1` when the next map starts, keeping `g_logRotate` older copies. It used to grow forever.
- **Strict port:** `net_strictPort 1` stops the server with an error when `net_port` is busy, instead of starting on one of the next 9 ports, where players and the masters don't look for it.

## libcod script functions and callbacks

- **More libcod callbacks and player methods (from zk_libcod, same names):** `_callbacksetup.gsc` can define `CodeCallback_Error(critical, function, message, position)` (script runtime errors, delivered on the next frame; in developer mode `position` is the `"file:line"` of the error, and `developer 2` reports errors without stopping the map), `CodeCallback_HitchWarning(msec)`, `CodeCallback_Pickup(type, weapon, name, quantity, clip, origin, angles)` (replaces the stock pickup), `CodeCallback_Suicide()` (replaces `suicide()`; `processSuicide()` kills), `CodeCallback_WeaponChange(index, name)` and one callback per button press: `Attack`, `Melee`, `Use`, `Reload`, `LeanLeft`, `LeanRight`, `Prone`, `Crouch`, `Stand`, `Ads`, `MeleeBreath`, `HoldBreath`, `Frag` and `Smoke` (`CodeCallback_<name>Button()`). New player methods: `isFiring`, `isMeleeing`, `isReloading`, `isThrowingGrenade`, `isUsingBinoculars`, `isRechambering`, `isShellShocked`, `isChatting`, `holdBreathButtonPressed`, `get`/`setCurrentWeaponAmmo`, `get`/`setCurrentWeaponClipAmmo`, `getCurrentWeaponSlot`, `get`/`setSpeed`, `get`/`setGravity`, `getGroundEntity`, `getViewOrigin`, `getPlayerstateFlags`, `getInactivityTime`, `getEnterTime` and `processSuicide`. Unlike zk_libcod, the weapon change and error callbacks never run inside player movement or the script VM, and a `suicide()` inside `CodeCallback_Suicide` does not loop.
- **Admin and server functions (from zk_libcod, same names):** player methods `muteClient`/`unmuteClient`, `setHiddenFromScoreboard` and `setHiddenFromServerStatus` with their `is…` getters (hidden players are left out of the scoreboard, or out of `getstatus` and the `getinfo` count), `setAllowSpectators`, `setConfigstringForPlayer`, `getServerCommandQueueSize`, `getCDKeyHash` and `getClientHudElemCount`; functions `setConsolePrefix`, `setNextTestClientName` and `resetTestClientNaming`. `CodeCallback_RemoteCommand(from, args)` receives accepted rcon commands and `processRemoteCommand()` runs them; it replaces `remotecommand(from, pointer)`, which crashed the server with any value a script could pass. `clientCommand()` (also `processClientCommand()`) now only works inside `CodeCallback_PlayerCommand`, for that player, instead of running leftover arguments that could be another player's. A map command, `killserver` or `quit` run with `cmd_executestring` or `processRemoteCommand()` no longer crashes the server (it runs once the script thread is done), and what a script set for a player with `setSpeed`, `setGravity` and the like no longer carries over to the next player in that slot.
- **Waypoint graphs with A\* and more script functions (from zk_libcod):** `graphCreate`, `graphAddNode`, `graphAddEdge`, `graphFindPath`, `graphFindClosestNode`, `graphAutodiscover`, `graphSave`/`graphLoad` and the rest of zk_libcod's `graph*` functions let bot scripts navigate a map (`src/libcod/gsc_graph.cpp`, ported under its MIT license). Unlike in zk_libcod, graphs are also cleared on a fast `map_restart` (every round of SD), a bad id or file returns undefined without ending the script thread, `graphLoad` refuses files over 64 MB and files with a negative or non-finite edge cost or a non-finite origin, and `graphSave` refuses `.iwd`, `.cfg` and `.gsc` names (also with a trailing `.` or space, or a `:`, which Windows would strip or read as a stream). `graphAutodiscoverEx` also takes an array of seed origins and floods from all of them at once, so a graph that reaches `sv_graphMaxNodes` is spread over the map instead of filling up around the first seed, and it keeps linking the nodes it has after the cap. Also new: `abs`, `floor`, `ceil`, `pow`, `atan2`, `roundTo`, `getMilliseconds`, `getMicroseconds`, `toHex`, `fromHex`, `ord`, `chr`, `getEntityCount`, `logPrintConsole` and the `getUserinfo`/`setUserinfo` methods; `bulletTrace` and `bulletTracePassed` take an optional content mask, and `bulletTrace` also returns `flags`, `contents` and `material`; with `sv_botUseTriggerUse 1`, a bot standing in a use trigger (such as an SD bomb zone) gets `self waittill("bot_trigger", trigger)`.
- **Weapon and combat functions (from zk_libcod, same names):** player methods `setWeaponSpreadScale`, `setTurretSpreadScale`, `setMeleeRangeScale`, `setMeleeWidthScale`, `setMeleeHeightScale`, `setFireRangeScale`, `setBulletMask`/`getBulletMask`, `setFireThroughWalls`, `enableBulletImpacts`/`disableBulletImpacts`, `useTurret`, `canUseTurret`, `stopUseTurret`, `canMantle`, `getWeaponAnimation`, `forceShot` and `noClip`; entity methods `spawnGrenade`, `getGrenadeFuseTime`/`addGrenadeFuseTime`, `isTurret`, `getTurretOwner`, `get`/`setWeaponItemAmmo`, `get`/`setWeaponItemClipAmmo` and `get`/`setItemQuantity`; functions `getWeaponFuseTime`, `getWeaponRaiseTime`, `getWeaponMoveSpeedScale`, `getWeaponDisplayName`, `isSemiAutoWeapon`, `ignoreWeapon` and `resetIgnoredWeapons`. Left out because the client predicts them and would stutter: zk_libcod's setters for jump height, step size and weapon move speed, and `setHoldingWeaponDown`.
- **zk_libcod names and more script functions:** zk_libcod's names now work for functions this fork already had under libcod's names (`executeCommand`, `sendCommandToClient`, `sendPacket`, `findConfigStringIndex`, `fremove`, `loadDir`, `getClientConnectState`, `connectionlessPacketToClient`/`ToServer`, `processClientUserinfoChange`, `throwGrenade`, `throwSmokeGrenade`, `setAim`, `setAnimation`), so scripts written for zk_libcod run unchanged. New entity methods `getTagOrigin`, `getTagAngles`, `hasTag`, `isLinkedTo`, `getVMin`, `getVMax`, `get`/`setClipmask`, `getContents` and `setLight`; player methods `overrideContents`, `isUseTouching`, `getProtocolString`, `setOriginAndAngles` and `setWalkValues` (bots); functions `makeString`, `makeClientLocalizedString`, `getCvarFlags`, `getSurfaceName`, `setNorthYaw`, `getMovers` and `get`/`setSavePersist`. `setAnim` with an animation name the server doesn't know returns false instead of stopping the map.
- **Per-player visibility, effects and collision (from zk_libcod, same names):** entity methods `hideFromPlayer` (the opposite of the stock `showToPlayer`; undone when that player's slot is freed) and `notSolidForPlayer`/`solidForPlayer` (a brush model one player walks through); player methods `playFxForPlayer`, `playFxOnTagForPlayer`, `earthquakeForPlayer`, `enableEarthquakes`/`disableEarthquakes`, `setNorthYawForPlayer`, `setCullFogForPlayer`, `setExpFogForPlayer`, `objective_player_add`/`_delete`/`_icon`/`_position`/`_state` (per-player compass objectives), `enableSilent`/`disableSilent` (the others stop hearing a player's steps and landings) and `setCollisionTeam`/`getCollisionTeam` (`"axis"`, `"allies"`, `"none"` or `"axis_allies"`). What a player walks through is also sent as not solid in that player's snapshots, so the client predicts the same as the server. Unlike zk_libcod, silenced events stay in the player's own playerState, so its prediction is unchanged. Left out: the manual snapshot entity list (zk_libcod's version breaks delta compression) and the talker icons (it fakes voice packets).
- **Physics for scripts (from zk_libcod, same names):** script models can fall and bounce: `enableGravity([collideModels], [alignToGround])`, `disableGravity`, `isGravityEnabled`, `enableBounce([parallel], [perpendicular])`, `disableBounce`, `set`/`add`/`getEntityVelocity` and `set`/`getMaxEntityVelocity`, with `land` and `bounce` notifies (surface name, ground entity). They move on the trajectories the client already extrapolates, so it draws the same path; unlike zk_libcod, the speed limit is also sent to the client, models no longer stick to walls and their angles survive `enableGravity`. With `g_bulletDrop 1`, `enableBulletDrop`/`disableBulletDrop`, `setBulletVelocity` and `setBulletDrag` make a player's bullets fly over the next frames, dropping and slowing down, with impacts, penetration and the bullet settings above still applying; zk_libcod's bullet models are left out.
- **JSON (from zk_libcod, same names):** `json_parse`, `json_stringify`, `json_load`, `json_save` and the non-blocking `json_load_async`/`json_save_async` with `json_async_done`/`json_async_result` turn JSON into GSC arrays and back, in memory or in files of the mod folder. Built on yyjson, which is compiled into the binary. Unlike zk_libcod, the async writer also works on Windows and saving `.iwd`, `.cfg`, `.gsc`, `.so` or `.dll` files is refused.
- **Sounds through voice chat (from zk_libcod, same names):** `loadSoundFile` encodes an 8192 Hz mono 16-bit sound (raw PCM or WAV) into Speex in the background, and `playSoundFile` plays it to a player as voice chat from any player, with `sound_file_done`/`sound_file_stop` notifies; also `stopSoundFile`, `isPlayingSoundFile`, `getRemainingSoundFileDuration`, `getSoundFileDuration` and `loadSpeexFile`/`saveSpeexFile`. libspeex is compiled into the binary. Unlike zk_libcod, sounds take the memory they need (not a 513 MB array), the playback follows the real frame time, and Speex files can't overflow the voice queue. A WAV with a broken chunk size is refused instead of hanging the server, and chunks after the samples (such as `LIST` tags) are neither played nor counted in the duration. A player whose voice queue is full gets the rest of the sound on the next frames instead of losing those packets, and `saveSpeexFile` refuses names that end in a dot or a space, which Windows drops, so `evil.cfg.` can no longer get past its refusal of `.iwd`, `.cfg`, `.gsc`, `.so` and `.dll` names.
- **HTTP and WebSocket clients (from zk_libcod, same names and callbacks):** `httpFetch(url, method, data, headers, timeout, ::onDone, ::onError, [allowInsecure])` makes one request and calls `onDone(status, body, headers)` (headers in an array keyed by lowercase name) or `onError(message)` on a later frame; `webSocketConnect(url, headers, ::onConnect, ::onMessage, ::onClose, ::onError, [reconnectDelayMs], [pingIntervalMs], [allowInsecure])` returns an id from 0 to 15 (or -1), reconnects on its own and delivers whole text messages, with `webSocketSendText(id, text)` and `webSocketClose(id)`; the `http_fetch` and `websocket_*` spellings work too. Requests and connections run on their own threads, so a slow server never holds up the game, and they belong to the level: on a map change or `map_restart` requests are cancelled and connections closed, and nothing arrives late. `http`, `https`, `ws` and `wss` URLs only; bodies, headers and messages over 65000 bytes go to `onError` (messages are dropped); at most 16 requests and 16 connections at once; redirects are not followed (a 3xx comes to `onDone` with its `location` header). A `timeout` of 0 means the longest, a day. A response with a NUL or a control character in a header name, more than 100 header lines, a `Content-Length` that isn't plain digits (or repeated with different values) or more than 5 interim responses goes to `onError`. Each connection keeps at most 1 MB of messages the script hasn't taken yet (the rest are dropped and logged) and delivers at most 64 events per frame. Unlike zk_libcod, which is an optional Linux build with libwebsockets, this is built in on Linux and Windows with Mbed TLS 3.6 (`src/libcod/mbedtls`, Apache-2.0), WebSocket certificates are checked too (against the system's CA list or `sv_httpCaFile`, unless `allowInsecure` is set), a bad `webSocketConnect` URL returns -1 instead of retrying, and `sv_httpAllowedHosts` can limit the hosts scripts reach.
- **More bot buttons in libcod:** the script methods `useButton`, `throwSmoke` and `holdBreath` make a bot press use (to plant or defuse the bomb), throw a smoke grenade or hold its breath, like the existing `fireWeapon` and `throwNade`. Each takes `1` to press and `0` to release.

## Bots mod

- **Simple bots:** `mods/bots` is a small script mod whose bots navigate each map over a waypoint graph built with the libcod `graph*` functions: the first time a map is played the graph is generated from all its spawn points at once and saved as `waypoints/<map>_v2.graph` in the mod folder, and later loads read it. With nobody in sight they follow what they last saw or heard shooting, patrol towards the enemy side, and only after 20 s without contact head for the nearest enemy. They aim down the sight at range, throw grenades at mid range, knife up close and reload between fights. In SD and CTF each life a bot draws a role: attackers plant the bomb or hunt, defenders guard a bomb site or hunt, and once the bomb is planted the defenders go to defuse it while the planters guard it; in CTF bots steal and bring home the enemy flag, or defend their own, chase its carrier and return it when it is dropped (SD in dual bomb mode is played without objectives). `scripts/install_bots.py` installs it; `bots_count`, `bots_skill` and `bots_debug` control them.

## Testing tools

- **Test client that reads snapshots:** `scripts/cod2snap.py` parses everything the server sends to a client (gamestate, server commands, snapshots with the playerstate, entities and client states, in 1.0 and 1.3), and `cod2client.read_frames()` returns one frame per snapshot, so tests can check what one client receives.
- **HTTP and WebSocket test:** `scripts/http_test.py` runs local HTTP, HTTPS, WS and WSS servers, makes a test mod call `httpFetch` and `webSocket*` against them, and checks the results, the certificate checks, the limits, malformed responses, WebSocket floods, that the server keeps answering during a slow request and that a map change or `map_restart` drops the old level's requests and connections.
- **Smoke test:** `scripts/smoke_test.py` starts the Linux server against a real game folder and checks that it loads a map, answers queries and lets a minimal client (`scripts/cod2client.py`) connect, receive the gamestate, enter the game and send commands, including in fragmented messages. A second run in internet mode (`dedicated 2`) heartbeats to a fake master on `127.0.0.1` and checks the heartbeats, the status sent on its own, the replies to the master's queries and the flatline when SIGTERM stops it, with the real masters cleared so nothing leaves the machine. It also checks that SIGTERM exits with code 0 after closing `games_mp.log`, that a console log that can't be opened is reported once and rotates nothing, that `g_logRotateSize` rotates the game log and that `net_strictPort` stops a second server on a busy port.

## New variables

| Variable | Default | Range | Description |
| --- | --- | --- | --- |
| `sv_rconMaxAttempts` | `5` | 0–100 | Wrong rcon passwords allowed per IP before the lockout. `0` disables the lockout. |
| `sv_rconLockTime` | `600` | 0–86400 | Lockout duration in seconds. It is also the window in which attempts are counted. |
| `sv_rconWhitelist` | `""` | — | IP addresses, separated by spaces or commas, that are never locked out of rcon. Host names are ignored. |
| `logfileName` | `""` | — | Console log file, in `fs_homepath/<mod>`. Empty uses `console_mp_server.log`; names with `..` or a full path are ignored. |
| `logfileRotate` | `0` | 0–1000 | Logs of previous runs kept when the server starts, as `<name>.1` (newest) to `<name>.N`. |
| `logTimestamps` | `0` | 0–1 | `1` starts each console log line with the date and time. |
| `g_logRotateSize` | `0` | 0–2047 | Size in MB at which `g_log` (`games_mp.log`) is rotated when the next map starts. `0` never rotates it. |
| `g_logRotate` | `1` | 1–1000 | Older game logs kept when `g_logRotateSize` rotates it, as `<name>.1` (newest) to `<name>.N`. |
| `net_strictPort` | `0` | 0–1 | `1` stops the server when `net_port` is busy instead of trying the next 9 ports. Only read at startup, so set it on the command line. |
| `sv_logRcon` | `1` | 0–1 | `0` leaves accepted rcon commands out of the log. Wrong passwords are always logged. |
| `sv_authorizeServer` | `cod2master.activision.com` | — | CD key authorization server. A new value is used from the next connection. |
| `sv_authorizePort` | `20700` | 1–65535 | Port of the authorization server. |
| `g_forceRate` | `0` | 0–25000 | Rate given to every client instead of its own (minimum 1000). `0` keeps the client's. |
| `g_forceSnaps` | `0` | 0–30 | Snapshots per second given to every client. `0` keeps the client's. |
| `sv_kickMessages` | `1` | 0–1 | `0` hides the message that tells everyone a player was kicked. |
| `sv_timeoutMessages` | `1` | 0–1 | `0` hides the message that tells everyone a player timed out. |
| `sv_botUseTriggerUse` | `0` | 0–1 | `1` sends a bot a `bot_trigger` notify, with the trigger, while it stands in a use trigger it could use. |
| `g_bulletDrop` | `0` | 0–1 | `1` lets `enableBulletDrop` give a player's bullets travel time and drop. |
| `g_bulletDropMaxTime` | `10000` | 50–60000 | Milliseconds a dropping bullet flies before it is dropped. |
| `sv_httpAllowedHosts` | `""` | — | Hosts `httpFetch` and `webSocketConnect` may reach, separated by spaces or commas; `*.example.com` allows its subdomains. Empty allows every host. |
| `sv_httpCaFile` | `""` | — | PEM file with the certificates `https` and `wss` trust. Empty uses the system's: `/etc/ssl/certs/ca-certificates.crt` or `/etc/pki/tls/certs/ca-bundle.crt` on Linux, the certificate store on Windows. On Windows the store only holds the root certificates the system has already downloaded, so set this to a CA bundle (such as the `cacert.pem` from curl) if `https` or `wss` hosts fail verification. The file is read again when the variable changes or after an hour. |
| `g_debugGraph` | `0` | 0–1 | `1` prints debug messages from the graph functions. |
| `sv_graphAstarMaxIterations` | `0` | 0–100000 | Maximum nodes one `graphFindPath` expands. `0` means no limit. |
| `sv_graphAstarWeight` | `1` | 1–2 | A\* heuristic weight. Above `1`, paths are found faster but can be longer. |
| `sv_graphMaxGraphs` | `8` | 1–64 | Maximum number of graphs at once. |
| `sv_graphMaxNodes` | `8192` | 64–65535 | Maximum nodes in one graph. |
