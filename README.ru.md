# CoD2rev_Server (форк JotaJazz)

[Español](README.es.md) · [English](README.md) · [Português](README.pt.md) · [Français](README.fr.md) · [Deutsch](README.de.md) · **Русский**

Исходный код выделенного сервера **Call of Duty 2** (версии 1.0 и 1.3), полученный методом обратной разработки.
Он исправляет ряд ошибок оригинальных бинарных файлов и позволяет расширять возможности сервера.

Этот репозиторий — форк [voron00/CoD2rev_Server](https://github.com/voron00/CoD2rev_Server), где и была проделана вся работа по обратной разработке. Здесь добавлены только изменения, описанные в разделе [Изменения в этом форке](#изменения-в-этом-форке).

Изменения этого форка, включая этот README и его переводы, написаны с его помощью. Сделанные так коммиты содержат в сообщении строку `Co-Authored-By: Claude`, поэтому их можно найти в истории через `git log`.
- **Отношения с оригиналом:** этот форк забирает изменения из оригинального репозитория, когда они появляются, но свои туда не отправляет. Со временем он, вероятно, будет всё сильнее от него отличаться.
- **Чем это не является:** это не официальный проект, и он не связан с Activision, Infinity Ward или автором оригинального репозитория. В нём нет файлов игры.

## Изменения в этом форке

- **Сборка под Windows с помощью MinGW** (32 бита), в том числе кросс-компиляция из Linux.
- **Пароли не попадают в лог:** `rcon_password` и `sv_privatePassword` отображаются в журнале консоли как `********`.
- **Блокировка rcon после неудачных попыток:** после нескольких неверных паролей rcon некоторое время игнорирует этот IP-адрес. Верный пароль сбрасывает счётчик, а адреса `127.x.x.x` никогда не блокируются.
- **Мастер-серверы:**
  - в `sv_master2` по умолчанию указан `master.cod2x.me`, мастер-сервер сообщества CoD2x;
  - формат `хост:порт` в `sv_master1`–`sv_master5` теперь работает;
  - при ошибке DNS запрос повторяется, а мастер-сервер не удаляется.
- **Версия игры выбирается при сборке:** сервер можно собрать как 1.0 или как 1.3.
- **Исправлено переполнение при клиентах Game Pass:** отправка системной информации клиенту с протоколом 119 могла переполнить буфер и обрушить сервер.
- **Большие сообщения от клиентов 1.3:** фрагментированные сообщения от клиентов 1.3 читались неверно и отбрасывались; теперь они читаются в формате 1.3.
- **Ограничение длины строк в скриптовых функциях libcod:** `printf` и `sprintf` из libcod, асинхронные вызовы SQLite и exec и переименование игрока больше не пишут за пределы своих буферов, когда скрипт передаёт длинные строки.
- **Более простая сборка:** `make` сразу собирает 32-битный бинарный файл для Linux, `make windows` выполняет кросс-компиляцию под Windows, а GitHub Actions собирает все варианты при каждом push.
- **Пример `server.cfg`:** `scripts/server.cfg.example` перечисляет все переменные, которые регистрирует сервер; `scripts/gen_server_cfg.py` заново создаёт его по исходному коду.
- **`dedicated` теперь учитывается:** `+set dedicated 1` игнорировался, и каждый сервер объявлял себя мастер-серверам. Теперь `1` не показывает сервер в публичном списке, а `2`, значение по умолчанию, объявляет его.
- **Файлы игры на дисках Windows:** сборка для Linux не видела файлы игры в файловых системах с большими номерами inode, например на дисках Windows под WSL. Теперь она собирается с 64-битными смещениями файлов.
- **Стабильные игровые часы в Linux:** сервер измерял время по системным часам, поэтому каждая корректировка времени (NTP, синхронизация времени виртуальной машины) на мгновение замораживала игру. Теперь используются монотонные часы.
- **Защита сетевого ввода:** подключённый игрок мог уронить сервер или перезаписать его память слишком большим сжатым сообщением, фрагментированным сообщением, именем с `%` (стандартные режимы игры пишут его в лог), `callvote clientkick` с отрицательным номером или голосовыми пакетами. Теперь эти пути проверяют границы, а файлы прерванных HTTP-загрузок закрываются.
- **Боты после смены карты:** после смены карты боты оставались подключёнными, но вне игры, занимая свои слоты, поэтому мод ботов добавлял новых, пока сервер не заполнялся. Теперь они возвращаются в игру сразу после загрузки новой карты.
- **Адрес прокси libcod и загрузки:** реальный адрес, который локальный прокси передаёт в ключе `ip` в userinfo, принимается только с `127.0.0.1`, должен быть адресом IPv4 и сбрасывается при каждом подключении. Команда `donedl` от игрока, который уже в игре, больше не заставляет сервер заново отправлять весь gamestate.
- **Загрузки и пароли:** проверка, которая должна была запрещать клиентам скачивать оригинальные `iw_*.iwd`, никогда не срабатывала, поэтому любой клиент мог их получить (сотни МБ каждый); теперь они отклоняются, как и серверные `_svr_` iwd, в том числе до перенаправления на HTTP. Загрузки больше не зависают, если во время них сменилась карта, слишком большое для распаковки сообщение клиента приводит к его отключению, а не обрезается, а rcon, `g_password` и `sv_privatePassword` сравниваются за постоянное время.
- **Баны, игровой лог и другие исправления, найденные в zk_libcod:** `addip` и `g_banIPs` хранили список забаненных адресов, который ничто не проверяло; теперь он применяется при подключении, в том числе к игрокам за локальным прокси. Последний адрес в `g_banIPs` больше не пропускается, а слишком длинный `addip` больше не переполняет стек. Переводы строк в сообщениях чата и именах игроков могли записывать поддельные строки в `games_mp.log` и разрывать ответы `getstatus`; теперь они удаляются. Неверный пароль rcon больше не задерживает верный, `userinfo` больше не съедает следующее сообщение чата, а удержание кнопки гранаты без гранат больше не скрывает от других выстрелы и шаги игрока. Сущности эффектов взрывов гранат теперь освобождаются, а не копятся до конца карты, скрипт, удаляющий занятый станковый пулемёт, больше не завершает карту, а слишком длинное имя карты, переданное в функцию скрипта, больше не останавливает сервер.
- **Отчёты о падениях:** при падении сервер записывает сигнал или исключение, адрес сбоя и адреса вызовов в консоль и в `crash.log` в `fs_homepath`. `addr2line -f -e <бинарник> <адрес>` превращает их в места в исходном коде. В Linux процесс затем завершается тем же сигналом, что и раньше, так что core-дампы по-прежнему работают.
- **Настройки логов и администрирования:** лог консоли можно переименовать (`logfileName`), сохранять логи прошлых запусков (`logfileRotate`) и начинать каждую строку с даты и времени (`logTimestamps`). Принятые команды rcon можно не писать в лог (`sv_logRcon`), сервер авторизации CD-ключей можно сменить (`sv_authorizeServer`, `sv_authorizePort`), сервер может навязать всем клиентам rate и частоту снапшотов (`g_forceRate`, `g_forceSnaps`), а сообщения о кике или тайм-ауте можно отключить (`sv_kickMessages`, `sv_timeoutMessages`). Имена совпадают с zk_libcod, поэтому его конфиги продолжают работать.
- **Проверочный тест:** `scripts/smoke_test.py` запускает сервер для Linux с настоящей папкой игры и проверяет, что он загружает карту, отвечает на запросы и принимает минимального клиента (`scripts/cod2client.py`), который получает gamestate, входит в игру и отправляет команды, в том числе фрагментированными сообщениями.
- **Простые боты:** `mods/bots` — небольшой скриптовый мод, боты которого идут к ближайшему противнику и стреляют по тем, кого видят, используя функции ботов из libcod. Путевых точек у них нет. `scripts/install_bots.py` устанавливает мод; ботами управляют `bots_count` и `bots_skill`.
- **Больше кнопок для ботов в libcod:** скриптовые методы `useButton`, `throwSmoke` и `holdBreath` заставляют бота нажать «использовать» (чтобы заложить или обезвредить бомбу), бросить дымовую гранату или задержать дыхание, как уже существующие `fireWeapon` и `throwNade`. Они принимают `1`, чтобы нажать, и `0`, чтобы отпустить.
- **Меньше зависаний и более чистый запуск:** имя мастер-сервера определяется один раз, а не при каждом истечении ожидания авторизации, и сервер больше не выдаёт предупреждение на каждый `+set` в командной строке.
- **Скрипты запуска:** `scripts/windows/iniciar_cod2rev.bat` и `scripts/linux/iniciar_cod2rev.sh`, с режимом локальной сети и режимом интернета.

### Новые переменные

| Переменная | По умолчанию | Диапазон | Описание |
| --- | --- | --- | --- |
| `sv_rconMaxAttempts` | `5` | 0–100 | Сколько неверных паролей rcon допускается с одного IP до блокировки. `0` отключает блокировку. |
| `sv_rconLockTime` | `600` | 0–86400 | Длительность блокировки в секундах. Это же окно, в котором считаются попытки. |
| `logfileName` | `""` | — | Файл лога консоли в `fs_homepath/<мод>`. Пустое значение — `console_mp_server.log`; имена с `..` или полным путём игнорируются. |
| `logfileRotate` | `0` | 0–1000 | Сколько логов прошлых запусков сохранять при старте: от `<имя>.1` (самый новый) до `<имя>.N`. |
| `logTimestamps` | `0` | 0–1 | `1` начинает каждую строку лога консоли с даты и времени. |
| `sv_logRcon` | `1` | 0–1 | `0` не пишет принятые команды rcon в лог. Неверные пароли записываются всегда. |
| `sv_authorizeServer` | `cod2master.activision.com` | — | Сервер авторизации CD-ключей. Новое значение действует со следующего подключения. |
| `sv_authorizePort` | `20700` | 1–65535 | Порт сервера авторизации. |
| `g_forceRate` | `0` | 0–25000 | Rate, который получает каждый клиент вместо своего (минимум 1000). `0` оставляет клиентский. |
| `g_forceSnaps` | `0` | 0–30 | Снапшотов в секунду для каждого клиента. `0` оставляет клиентское значение. |
| `sv_kickMessages` | `1` | 0–1 | `0` скрывает сообщение для всех о том, что игрока кикнули. |
| `sv_timeoutMessages` | `1` | 0–1 | `0` скрывает сообщение для всех о том, что игрок отключился по тайм-ауту. |

## Версии игры

- **Версия выбирается при сборке.** По умолчанию сервер собирается как 1.0 (протокол 115); с `PROTOCOL=118` он собирается как 1.3. Сервер сообщает эту версию мастер-серверам, поэтому появляется в списке серверов у клиентов той же версии.
- **Сборка 1.0 принимает и другие версии по прямому IP.** С libcod, который включён по умолчанию, она принимает подключения с протоколами от 115 до 119, включая 1.3 (протокол 118) и версию из Game Pass (протокол 119). Подключение к этой сборке по прямому IP проверено, в том числе клиентом CoD2x 1.4.x.
- **Сборка 1.3 принимает только клиентов с протоколом 118.** Её запускали в Linux и в Windows, где она загружает карту и отвечает как 1.3, а на сборке для Linux уже играли клиентом CoD2x 1.4. Клиенты [CoD2x](https://github.com/callofduty2x/CoD2x) 1.4 тоже подключаются по протоколу 118, а в их списке серверов показываются только серверы, сообщающие протокол 118 или 120, поэтому увидеть они могут именно эту сборку.

## Сборка

Результат помещается в `bin/`, промежуточные объектные файлы — в `obj/`.

### Windows (кросс-компиляция из Linux с помощью MinGW)

Нужен 32-битный компилятор MinGW-w64 (`i686-w64-mingw32`).

```bash
make windows
```

Создаёт `bin/cod2rev_win32.exe`.

### Linux

Сервер — это 32-битный бинарный файл x86. В 64-битной системе нужна поддержка 32 бит в GCC (в Debian и Ubuntu это пакеты `gcc-multilib` и `g++-multilib`):

```bash
make
```

Создаёт `bin/cod2rev_lnxded`.

### Версия игры

Добавьте `PROTOCOL=118` к команде `make`, чтобы собрать сервер как 1.3; без него или с `PROTOCOL=115` сервер собирается как 1.0. У каждой платформы и версии свои объектные файлы в `obj/`, поэтому переключаться между ними можно без `make clean`. Автоматическая сборка публикует обе версии для каждой платформы.

### Автоматическая сборка

При каждом push в `master`, который меняет код, обе версии собираются в GitHub Actions ([`.github/workflows/build.yml`](.github/workflows/build.yml)). Готовые бинарные файлы можно скачать как артефакты на вкладке [Actions](https://github.com/JotaJazz/CoD2rev_Server/actions) репозитория.

### Параметры Makefile

| Параметр | По умолчанию | Описание |
| --- | --- | --- |
| `WITH_LIBCOD` | `true` | Включает скриптовые расширения libcod (боты, игроки, сущности, оружие, утилиты и т. д.). |
| `WITH_SQLITE` | `true` | Скриптовые функции для SQLite. |
| `WITH_MYSQL` | `false` | Скриптовые функции для MySQL. Требуется клиентская библиотека MySQL. |

`make clean` удаляет бинарный файл и объектные файлы.

## Запуск

Серверу нужны файлы оригинальной игры (папка `main` с файлами `.iwd`), которых в этом репозитории нет. Нужна собственная копия Call of Duty 2.

### Windows

1. Скопируйте `cod2rev_win32.exe` и `scripts/windows/iniciar_cod2rev.bat` в папку игры, рядом с `main`.
2. Положите `server.cfg` в `main`. [`scripts/server.cfg.example`](scripts/server.cfg.example) задаёт обычные настройки и перечисляет все остальные переменные, которые регистрирует сервер, со значениями по умолчанию (комментарии на английском).
3. Запустите `iniciar_cod2rev.bat`.

Скрипт запускает сервер на порту `28970`, чтобы не конфликтовать с клиентом игры, который на том же компьютере использует `28960`, и загружает карту `mp_toujane`. По умолчанию он запускается в режиме локальной сети (`dedicated 1`, локальная сеть или прямой IP); запустите `iniciar_cod2rev.bat internet`, чтобы объявить сервер в публичном списке (`dedicated 2`).

### Проверка ключей

Сервер обращается к `cod2master.activision.com`, чтобы проверить ключ каждого клиента, который находится не в локальной сети. С `sv_cracked 1` запрос по-прежнему отправляется, но клиент принимается при любом ответе. Скрипты запуска включают эту переменную; уберите её из командной строки, если нужно требовать действительный ключ.

### Linux

Скопируйте `cod2rev_lnxded` и `scripts/linux/iniciar_cod2rev.sh` в папку игры, рядом с `main`, и положите `server.cfg` в `main`. Запустите `./iniciar_cod2rev.sh` для режима локальной сети или `./iniciar_cod2rev.sh internet`, чтобы объявить сервер в публичном списке. Скрипт использует порт `28960` и загружает карту `mp_toujane`.

`run_bin.sh` — тестовый скрипт оригинального проекта: он запускает `bin/cod2rev_lnxded` в режиме разработчика с включёнными читами и тестовыми ботами. Он годится как пример параметров, но не как конфигурация настоящего сервера.

## Тесты

Для `scripts/smoke_test.py` нужны собранный сервер и папка игры:

```bash
python3 scripts/smoke_test.py /путь/к/CoD2
make PROTOCOL=118 && python3 scripts/smoke_test.py /путь/к/CoD2 --protocol 118
```

Он запускает сервер в режиме LAN с временной домашней папкой, поэтому папка игры только читается. Он проверяет, что сервер загружает карту и отвечает на `getinfo`, `getstatus` и rcon, а `scripts/cod2client.py`, минимальный клиент, может подключиться, получить gamestate, войти в игру и отправлять команды, в том числе в сообщении, разбитом на фрагменты. Используйте папку игры с оригинальными файлами `.iwd`: моды в `main`, заменяющие скрипты режимов игры, могут не дать карте загрузиться.

Чтобы искать ошибки памяти, соберите сервер с AddressSanitizer в отдельной папке и передайте этот бинарный файл через `--binary`:

```bash
make OBJ_ROOT=/tmp/asan/obj BIN_DIR=/tmp/asan/bin \
  CFLAGS="-fno-pie -O1 -g -fno-omit-frame-pointer -mfpmath=387 -DNDEBUG -DPROTOCOL_VERSION=115 -MMD -MP -m32 -D_FILE_OFFSET_BITS=64 -fsanitize=address" \
  LFLAGS="-no-pie -m32 -fsanitize=address"
```

`CFLAGS`, заданный в командной строке, заменяет значение из Makefile, поэтому `-m32` и `-D_FILE_OFFSET_BITS=64` нужно указать снова. Если оставить такую сборку поработать какое-то время с модом ботов и коротким `sv_mapRotation`, будут проверены и смены карт, и сама игра.

## Структура репозитория

| Путь | Содержимое |
| --- | --- |
| `src/server` | Логика сервера: клиенты, сеть, rcon, мастер-серверы. |
| `src/game`, `src/bgame` | Игровая логика. |
| `src/script` | Виртуальная машина скриптов GSC. |
| `src/qcommon`, `src/universal` | Общий код: команды, переменные (dvars), файловая система, сеть. |
| `src/xanim` | Модели и анимации. |
| `src/stringed` | Локализованные строки. |
| `src/libcod` | Скриптовые расширения libcod, с SQLite и заголовками MySQL. |
| `src/win32`, `src/unix` | Код, зависящий от платформы. |
| `src/zlib` | Копия zlib. |
| `test` | Материалы обратной разработки: база данных IDA, таблицы смещений и тестовый загрузчик. |
| `scripts` | Скрипты запуска для Windows и Linux, пример `server.cfg` и его генератор, установщик ботов, а также проверочный тест с минимальным клиентом. |
| `mods/bots` | Скриптовый мод простых ботов. |
